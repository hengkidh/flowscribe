# flowscribe-init

Bootstraps `.flowscribe/` for a codebase that has no documentation yet. The goal is a **small,
accurate** first version that the next agent can trust, not a complete one.

## Before you start
- Read `.flowscribe/config.yaml` and the contract in `.flowscribe/schema/v1/` (the JSON Schemas define
  every allowed field; anything else is rejected).
- The security rules in the flowscribe block of `AGENTS.md` apply to everything you write.
- Do **not** open `.env`, `.env.*`, credential files, database dumps or `storage/` / `logs/` contents.
  Learn variable names from `.env.example` or from the code that reads them.

## Steps
1. **Map the stack** from manifest files (`composer.json`, `package.json`, `go.mod`, `pyproject.toml`, …)
   and the framework's routing files. Note the stack for `index.yaml` → `app.stack`.
2. **Find modules**: group the code by feature or domain (e.g. `orders`, `payments`, `auth`), not by
   technical layer. Aim for 3–12 modules. For each, write `.flowscribe/modules/<id>.md` from
   `.flowscribe/templates/module.md`:
   - `files` lists globs that really match files; `entrypoints` lists the 1–3 files to open first.
   - `env` lists variable **names** only.
   - The body explains responsibilities and gotchas you can verify in the code. Do not guess.
3. **Find the main flows**: the 2–5 journeys that matter most to the business (sign-up, checkout,
   approval, …). Write `.flowscribe/flows/<id>.md` from the template. Use routes and calls you found in
   the code; mark anything you could not confirm with `status: draft`.
4. **Write the index** (see "Index" below).
5. **Self-check** (see "Checks" below), then report to the user: what you documented, what you left as
   `draft`, and what you could not determine.

## Index
`.flowscribe/index.yaml` is generated from the frontmatter, never written from memory:
```yaml
# GENERATED by flowscribe — do not edit by hand.
flowscribe: 1
generated: true
app: { name: <app name>, summary: <≤240 chars>, stack: [<stack>] }
read_first: [<at most 5 document paths>]
modules:   [{ id, path, summary, status }]   # one per file in modules/, sorted by id
flows:     [{ id, path, summary, status }]
decisions: [{ id, path, summary, status }]
```
Copy `id`, `summary` and `status` exactly from each document's frontmatter.

## Checks
If the `flowscribe` CLI is on `PATH`, run `flowscribe check` and fix every error. Otherwise verify by hand:
- every document validates against `.flowscribe/schema/v1/document.schema.json` (no unknown fields);
- file name equals `id`; ids are unique; every referenced id (`next.to`, `modules`, `depends_on`, …) exists;
- every non-terminal step has `next`, and each flow has a step with `end`;
- no secret values, hosts, IPs, URLs or personal data anywhere — frontmatter **or** body.
