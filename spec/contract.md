# flowscribe document contract — v1

This is the contract every flowscribe document follows. Skills write it, `flowscribe check`
validates it, and the diagram, video and handover generators read it. Anything a tool needs
lives in the YAML frontmatter; anything a human needs (context, reasons, gotchas) lives in
the Markdown body.

Machine-readable schemas:
- `schema/v1/document.schema.json` — frontmatter of every `.md` under `.flowscribe/`
- `schema/v1/index.schema.json` — `.flowscribe/index.yaml`

## 1. Layout

```
AGENTS.md                      entry point for any agent (flowscribe block: read order + security rules)
CLAUDE.md                      contains @AGENTS.md
.agents/skills/flowscribe-*/   the skills (copied to .claude/skills/ for Claude Code)
.flowscribe/
  config.yaml                  project settings (visibility, capture host allowlist)
  schema/v1/                   this contract as JSON Schema
  templates/                   starting points for each document type
  index.yaml                   GENERATED by `flowscribe index` — never edited by hand
  flows/<id>.md                type: flow
  modules/<id>.md              type: module
  decisions/<NNNN>-<id>.md     type: decision
  log/<YYYY-MM>.md             type: log
  private/                     git-ignored; same document types, never committed
  screens/                     git-ignored; captured screenshots, regenerated on demand
```

The file name (without `.md`, and without the `NNNN-` prefix for decisions) must equal `id`.

## 2. Fields shared by every document

| Field | Required | Rule |
|---|---|---|
| `flowscribe` | yes | Contract version. Always `1` for now. |
| `type` | yes | `flow`, `module`, `decision` or `log`. |
| `id` | yes | kebab-case, `^[a-z][a-z0-9-]{1,47}$`, unique per type. |
| `title` | yes | ≤ 80 chars. |
| `summary` | yes (not `log`) | One sentence, ≤ 160 chars. Copied into the index, so it is what agents read first. |
| `status` | yes | `draft`, `active` or `deprecated`. |
| `updated` | yes | `YYYY-MM-DD`. Set by the skill that last touched the document. |
| `audience` | no | `internal` (default) or `external`. Only `external` documents go into an external handover pack. |
| `files` | flow, module | Repo-relative paths or globs this document describes. Used for drift detection. |
| `tags` | no | Up to 8 kebab-case tags. |

Unknown fields are rejected (`additionalProperties: false`). This is deliberate: it keeps
documents predictable for every agent and leaves no free-form field where a secret could land.

## 3. `type: flow`

A flow is an ordered set of steps an actor goes through. It is the source for Mermaid diagrams,
screenshots and video storyboards.

| Field | Required | Rule |
|---|---|---|
| `actor` | yes | Who drives the flow: `customer`, `admin`, `system`, … (kebab-case). |
| `trigger` | yes | What starts it, ≤ 120 chars. |
| `steps` | yes | 1–20 steps. Longer flows are split and linked with a `subflow` step. |
| `modules` | no | Module ids this flow touches. |
| `related` | no | Other flow ids. |

### Step

| Field | Required | Rule |
|---|---|---|
| `id` | yes | kebab-case, unique inside the flow. |
| `kind` | yes | `screen`, `action`, `system`, `decision`, `external`, `subflow`. |
| `title` | yes | ≤ 60 chars. |
| `screen` | for `kind: screen` | `{ route, name? }`. `route` is a path starting with `/` — never a full URL or host. |
| `action` | no | What the actor does, ≤ 120 chars. |
| `calls` | no | What the step invokes — see below. |
| `states` | no | Named states the step can end in, e.g. `[pending, paid, failed]`. |
| `next` | no | The step id that follows, or a list of `{ when, to }` branches. Omitted on the last step. |
| `end` | no | `success` or `failure` — marks a terminal step. |
| `subflow` | for `kind: subflow` | Id of another flow. |
| `caption` | no | ≤ 60 chars, used as the on-screen caption in videos. |

### Call

Either a short string, or an object:

```yaml
calls:
  - POST /api/orders                     # shorthand = { type: http, target: "POST /api/orders" }
  - { type: webhook, target: payment-gateway, note: may arrive before redirect }
  - { type: job, target: SendInvoiceEmail }
```

`type` is one of `http`, `event`, `job`, `webhook`, `db`, `external`. `target` is a method + path,
a class/event name, or a **service name** — never a URL, host, IP or credential (`://` and `@` are rejected).

## 4. `type: module`

A module is a feature or area of the codebase.

| Field | Required | Rule |
|---|---|---|
| `kind` | yes | `feature`, `domain`, `infra` or `shared`. |
| `files` | yes | See §2. |
| `entrypoints` | no | The files or routes to open first, ≤ 10. |
| `depends_on` | no | Other module ids. |
| `env` | no | Environment variable **names** the module reads, e.g. `PAYMENT_SERVER_KEY`. Values are rejected by pattern. |
| `data` | no | Tables, models or collections the module owns. |

## 5. `type: decision`

An architecture decision record.

| Field | Required | Rule |
|---|---|---|
| `number` | yes | Integer, matches the `NNNN-` file prefix. |
| `date` | yes | `YYYY-MM-DD`. |
| `status` | yes | For decisions: `proposed`, `accepted`, `superseded` or `rejected`. |
| `supersedes` | no | Decision number this one replaces. |
| `affects` | no | Module or flow ids. |

Body sections: `## Context`, `## Decision`, `## Consequences`.

## 6. `type: log`

One file per month. The frontmatter only identifies it. Entries are short body sections:

```markdown
## 2026-11-05 — checkout: hold stock before payment
- Changed: OrderController, StockService
- Why: double-selling during slow payments
- Open: expiry job not scheduled yet
```

Summaries only. Never paste terminal output, stack traces with data, or config values.

## 7. Index (`.flowscribe/index.yaml`)

Generated from the frontmatter above, so it can never drift from the documents. It is the one file
an agent reads at the start of every task. Target size: under ~1,500 tokens for a medium app.
Each entry carries only `id`, `path`, `summary` and `status`; agents open a document only when its
summary is relevant.

## 8. Rules that JSON Schema cannot express (enforced by `flowscribe check`)

1. File name matches `id`; ids are unique per type.
2. Every `next.to`, `subflow`, `modules`, `related`, `depends_on` and `affects` reference exists.
3. Every non-terminal step has `next`; every flow has at least one step with `end`.
4. Every `files` entry matches at least one file in the repo.
5. Drift: a file listed in `files` changed in a commit that did not touch the document → warning
   (error in CI with `--strict`).
6. Secret scan over frontmatter **and** body: key/token patterns, high-entropy strings, URLs with
   credentials, private IPs and internal hostnames.
7. With `visibility: public` in `config.yaml`: no `audience: internal` document outside `private/`.
8. `index.yaml` equals what `flowscribe index` would generate.

## 9. Parsing

Frontmatter is parsed as **YAML 1.2, core schema, safe load only** (e.g. `yaml` v2 in Node,
`ruamel.yaml` safe mode in Python). No custom tags, no anchors pointing outside the document.
Dates such as `updated: 2026-11-05` must stay strings; YAML 1.1 parsers (PyYAML) turn them into
date objects and fail validation.

## 10. Versioning

`flowscribe: 1` pins the contract. Additive, optional fields stay in v1. Renaming or removing a field,
or making a field required, means v2 with a `flowscribe migrate` command. Tools refuse versions they
do not know rather than guessing.
